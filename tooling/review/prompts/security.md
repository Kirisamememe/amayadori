## 見る範囲

外から悪用できる穴と、守りの抜け。

- Analemma とのつなぎ:公開 API を、サーバー側(`src/lib/server/`・`+page.server.ts`・`+layout.server.ts`)の外から呼んでいないか。`ANALEMMA_INTERNAL_URL` の値(内部用のポートの URL)が、ブラウザに届くコード・load の戻り値・エラーの文・ログに出ないか。
- ブラウザに届く値:load の戻り値が、表示に要る項目だけか(公開 API の応答をそのまま返していないか)。公開していないページが、このサイトから見えないか。
- サーバーでだけ読めるモジュール:`$app/env/private` や `src/lib/server/` の値を、ビルドが止めない書き方で、ブラウザに届くコードに渡していないか。
- 入力の境界:route のパラメータ・search params・form の値の検証、パスや URL の組み立て、HTML として描く値(`{@html}` など)。
- 秘密の扱い:デプロイ用のトークンや環境変数の値が、ログ・エラーの文・応答・URL・コミットするファイルに出ないか。デプロイ用のトークンを、動いているサーバーに渡していないか。
- 応答のヘッダー:セキュリティに関わるヘッダーを、外したり弱めたりしていないか。
- CI と依存:workflow の `permissions`、外から来る値の渡し方(script injection)、actions の固定、install で流れる script。

## 見ない範囲

- 悪用につながらない、仕様どおりかどうかの誤り(ビジネスロジックの観点)。
- ページの見た目・操作・アクセシビリティ(UI/UX とアクセシビリティの観点)。
- 書き方・フォルダ・文書の置き場所などの、リポジトリの約束(規約やルールの遵守の観点)。
- 文書・コメント・テストの名前・ページの文言の言葉(言葉の観点)。

## 重要度の目安

- 訪問者が外から悪用できる、または公開していないコンテンツが見えるなら高。
- 内部用のポートの URL のような、守りの前提だけが外に出るなら中。
- 条件が重なったときだけ起きるなら中か低。
- 細工した入力でだけ起き、エラーのページとログで済み、データも漏れないなら実害無し。
